# Перепроверка всего после 0.6.1 (выпуск 0.7.1)

- Дата: 2026-11-03
- Предмет: всё, что изменилось с 0.6.1 (версия на продакшене) по 0.7.0: связи нескольких типов, крайний срок и
  «Начало не ранее», импорт и экспорт MS Project, номера строк, миграция `0007_plan_links`; полнота выпуска по
  плану ADR-0012 для 0.7.0
- Как проверяли: три независимые проверки, не участвовавшие в разработке, и сверка с ADR-0012
  1. **Обновление базы.** База 0.6.1 построена кодом 0.6.1 из снимка 1.0.1 с продакшена (19 планов, 463 строки, 157
     связей) и дополнена правками через API 0.6.1: связи всех типов с лагами, удалённые строки, комментарии,
     версии, архив, корзина, Jira, «По Делу», ключи интеграций, структура. Обновлена так, как в Docker
     (`migrate_on_start.py`), на SQLite и PostgreSQL 16; данные сравнены построчно и через API обеих версий; расчёт
     сроков 0.6.1 и 0.7.0 сравнён на каждом плане, на 193 смоделированных правках и 400 случайных планах; откат
     схемы и восстановление версий 0.6.1.
  2. **Поиск регрессий.** Наборы тестов 0.6.1 (сервер, модульные, e2e) на коде 0.7.0; чтение всей разницы
     0.6.1..0.7.0 и разрешённых конфликтов слияний; два стенда 0.6.1 и 0.7.0 рядом на одних данных (Playwright).
  3. **Настоящие файлы MS Project.** 181 файл: сохранённые MS Project 2002–2019 (данные MPXJ), 24 настоящих `.mpp`,
     сконвертированных MPXJ, файлы Aspose и GanttProject, план на 102 строки с русским текстом, праздниками 2026 и
     рабочей субботой, планы на 7 820 и 19 992 задачи. Импорт (разовый и мастер-копия), обновление мастер-копии
     после правок «в MS Project», выгрузка, проверка выгрузки по схеме и пересчётом планировщиком MPXJ по правилам
     MS Project, повторный импорт выгрузки.
- Результат: данные при обновлении не теряются. Найдены одна высокая, 7 средних и 9 низких проблем, а также 3
  невыполненных пункта ADR — всё исправлено в 0.7.1; на каждое исправление — тест, который падает на коде 0.7.0

Оценка: **критично** — потеря или раскрытие данных; **высоко** — сбой работы, неверный результат или обход прав;
**средне** — неудобство или риск при определённых условиях; **низко** — мелочь.

## Обновление 0.6.1 → 0.7.0 и регрессии

| # | Оценка | Найдено | Решение |
| --- | --- | --- | --- |
| П1 | Высоко | Задачи «по длительности в рабочих днях» при пересчёте брали длину из поля длительности, а у 27 из 152 таких задач перенесённых данных оно не совпадает с датами. Сразу после обновления три плана показали бы «Сроки 43 / 21 / 2 строк не согласованы со связями» (в 0.6.1 — ни одной), а правка одной задачи сдвигала цепочку до +7 дней вместо +1 | Строка, чьё начало (окончание) связи не сдвигают, не меняется — как в 0.6.1. Сдвинутая задача «в рабочих днях» сохраняет рабочие дни своих сроков, считая по датам. На перенесённом снимке число несогласованных строк совпадает с 0.6.1 в каждом плане |
| П2 | Средне | Версия плана 0.6.1 со связью подзадачи и её родительской задачи (разрешалась до 0.7.0) не восстанавливалась — ошибка 400 | Такие связи восстанавливаются из версий 0.6.1 и 0.7 |
| П3 | Средне | Такие связи нельзя было изменить (тип, лаг), они пропадали при копировании плана, выгрузке-загрузке JSON и отмене удаления строки | Правятся, копируются, возвращаются отменой; запрещено только создать новую или сменить её концы |
| П4 | Средне | Поиск числа («3») находил строки по номеру даже при скрытой колонке «Номер» — показывал весь третий раздел (51 строку вместо 29) | Номер ищется только при включённой колонке |
| П5 | Низко | Под названием строки пропал лаг связи («лаг +1 д») | Снова виден; при нескольких связях — «лаги +1 д, +2 рд» |
| П6 | Низко | JSON (формат 1.0): изменения связей не попадали в историю строки | Попадают в историю строки-последующей, как правки предшественника до 0.7.0 |
| П7 | Низко | Страница или скрипт 0.6.1 с циклом в поле «предшественник» — отказ всего пакета (в 0.6.1 — связь снималась) | Как в 0.6.1: связь снимается с отметкой на строке |
| П8 | Низко | Откат на 0.6.x после правок в 0.7: теряются связи сверх первой, связи вех, рабочие лаги; версии 0.7 в 0.6.1 восстанавливаются без связей — не было описано | Описано в руководстве по развёртыванию: восстановление копии или откат схемы командой и что при этом теряется |

Проверено и в порядке: все 23 прежние таблицы совпадают построчно (6 283 строки), 172 связи из 172 перенесены с
тем же типом и лагом (удалённая — удалённой), комментарии, история (1 551 событие), версии, корзина, доступ,
структура, настройки Jira и «По Делу» не тронуты; API 0.7.0 на тех же данных отличается от 0.6.1 только новыми
полями (связи, крайний срок); API интеграций (118 вызовов) — только полями `predecessors` и `deadline`; 18 из 20
версий 0.6.1 восстанавливаются точно (2 — П2); откат схемы сразу после обновления возвращает базу один в один,
0.6.1 на ней работает; схема совпадает с моделями. Наборы тестов 0.6.1 на коде 0.7.0: сервер 203 из 205,
модульные 225 из 232, e2e 76 из 78 — все отказы из-за намеренных изменений (поле предшественника строки заменено
связями); ни один тест 0.6.1 не удалён и не ослаблен; конфликты слияний разрешены верно. Расчёт сроков: кроме
задач «в рабочих днях», 0.6.1 и 0.7.0 совпадают на всех 17 планах, 193 правках, 164 правках с датами из Jira и 400
случайных планах.

## Пункты ADR-0012 для 0.7.0, которых не было

| # | Пункт | Решение |
| --- | --- | --- |
| А1 | 5.4: срок задачи Jira можно переносить в крайний срок, а не в окончание | Настройка «Срок задачи Jira: В окончание / В крайний срок» в «Сверке и настройках Jira»; сверка и автоперенос «Сроки» следуют ей |
| А2 | 5.5: номер строки — в выгрузке CSV и печати | CSV — столбец «Номер» (у мастер-копии — WBS из файла); PNG/PDF/SVG — номер перед названием при включённой колонке |
| А3 | 2: после импорта — версия «Импорт из MS Project» | Версия сохраняется после любой загрузки из файла |

Не входило в 0.7 по плану ADR-0012: критический путь и резерв, базовые планы и отклонения, календарь плана — 0.8.0;
загрузка исполнителей и временная шкала — 0.9.0; чтение `.mpp` напрямую — отдельный выпуск с конвертером.

Осталось как задумано и описано в руководстве: в мастер-копии статус и прогресс ведёт файл («Завершена» из «Пульса»
вернётся к «Новая», если в файле 0 %), связь между строками файла, добавленная в «Пульсе», при обновлении
удаляется (видна в плане обновления), изменённая заметка существующей задачи не переносится.
