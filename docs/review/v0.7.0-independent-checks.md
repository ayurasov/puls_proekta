# Независимые проверки 0.7.0

- Дата: 2026-11-02
- Предмет: ветка `v0.7.0` — связи нескольких типов, крайний срок и «Начало не ранее», импорт файла MS Project XML
  (разовый перенос и мастер-копия с обновлением из файла), выгрузка в MS Project XML, номера строк
- Как проверяли: две отдельные проверки, не участвовавшие в разработке, — сервера и клиента. Сервер — по коду,
  тестами на SQLite и PostgreSQL 16, файлами MS Project с нарочно испорченным и предельным содержимым (UTF-16 без
  BOM, вложенные сущности, даты 0001 и 9999 годов, RTF с `\'00`, 20 000 задач). Клиент — по коду и на работающем
  стенде (Playwright, два браузера одновременно, роли редактор и наблюдатель, экраны 390–1440 px, план на 5000 строк
  с цепочками связей, учебный файл «Внедрение CRM»)
- Результат: 5 высоких, 11 средних и 22 низких замечания — все исправлены; на каждое исправление — тест, который
  падает на прежнем коде. Повторный прогон проверочных тестов ревьюера: ни одна из ошибок больше не воспроизводится

Оценка: **критично** — потеря или раскрытие данных; **высоко** — сбой работы, неверный результат или обход прав;
**средне** — неудобство или риск при определённых условиях; **низко** — мелочь.

| С14 | Низко | Выгрузка могла дать UID ресурса больше 32 бит | UID ресурса берётся из ключа только в допустимом диапазоне, иначе выдаётся новый |
| С15 | Низко | Суммарная задача проекта считалась в пределе 20 000 задач | Не считается |
| С16 | Низко | Записи реестра об импорте в план шли в раздел «Планы» без проекта и не находились фильтром | Раздел «Гант» с указанием проекта |
| С17 | Низко | Предпросмотр позволял любому правящему проект узнать, у какого сотрудника какой email: ресурсы сопоставлялись по email со всеми пользователями | По email сопоставляет только администратор — ему адреса и так видны |

| С19 | Низко | Замена плана файлом с новым ресурсом занимала ключ прежнего исполнителя: у другого пользователя — 409, у того же — прежний исполнитель молча переименовывался | Новые исполнители получают свободные ключи; прежние остаются как были |

Проверено и в порядке: миграция `0007_plan_links` вверх, вниз и снова вверх на SQLite и PostgreSQL 16 (удалённые
строки, ссылки на группу и на себя, потерянные ссылки, первая связь при откате); проверки связей (повторы, циклы при
создании, изменении и восстановлении, связи с группой, повтор пакета, история на строке-последователе, перевод
прежнего `dependencyKey`); версии без связей восстанавливаются; копия плана и JSON сохраняют ключи связей; API
интеграций добавляет только предшественников и крайний срок; защита XML (DOCTYPE в UTF-8 и UTF-16 с BOM, внешние
сущности не загружаются, .mpp, ZIP, PDF и MPX распознаются, предел вложенности); коды типов связей, ограничений и
лагов, перенос связей с суммарных задач, правило «окончание в 08:00» — как в разделе 3 ADR-0012; порядок элементов
выгрузки — по схеме Project 2013, повторяющиеся GUID заменяются; выгрузка — с правом просмотра, email — только у
связанных исполнителей; ограничения частоты и 25 МБ (Flask и nginx); файл на 20 000 задач — предпросмотр 1,7 с,
применение 10,4 с, выгрузка 4,8 с.

## Клиент

| # | Оценка | Найдено | Решение |
| --- | --- | --- | --- |
| К1 | Высоко | Длинный автосдвиг уходил одним пакетом больше 2000 операций — сервер его отклонял, и правка пропадала; «Выровнять по связям» на большом плане тоже не срабатывало | Большие правки отправляются частями до 1500 операций по порядку, отмена — одна; если часть отклонена, остальные не отправляются и план перечитывается |
| К2 | Высоко | План из MS Project не совпадал с расчётом «Пульса»: сразу после импорта «Сроки 16 строк не согласованы со связями», а смена статуса сдвигала эти строки, в том числе на выходные | Импорт переводит лаги по правилам «Пульса» (SF, календарные лаги с переходом на рабочий день, лаги в часах) и проверяет, что расчёт воспроизводит каждую дату файла; сверка серверного расчёта с клиентским — отдельным тестом. Автосдвиг запускается, только если меняется расписание строки, а не статус |
| К3 | Средне | Охват автосдвига на плане с обратным порядком цепочки считался 11,4 с — страница замирала на 10 с после одной правки | Один обход последователей и вложенных строк — мгновенно |
| К4 | Средне | Ответ 409 при применении не показывался, а «Заменить» снова становилась доступна с устаревшим предпросмотром | Конфликт остаётся на экране, устаревший предпросмотр применить нельзя до повторной проверки |
| К5 | Средне | Неотправленные правки открытого плана переживали замену или обновление из файла и затем перезаписывали их | Перед заменой и обновлением открытого плана его правки отправляются; если не удалось — применение не начинается |
| К6 | Средне | Список «Добавить предшественника» создавал связь на каждое нажатие стрелки | Список только выбирает; связь добавляется кнопкой «Добавить» или Enter |
| К7 | Средне | Копия строки мастер-копии получала номер и идентификаторы MS Project оригинала | Копия их не получает (Ctrl+D, меню, перетаскивание с Ctrl); сервер их тоже не принимает |
| К8 | Средне | Тот же файл нельзя было выбрать повторно после ошибки, повторить проверку было нечем | Можно выбрать тот же файл; кнопка «Проверить ещё раз» |
| К9 | Средне | «Экспорт → MS Project (XML)» не учитывал неотправленные правки, а сбой сети показывался как «Failed to fetch» | Перед выгрузкой правки отправляются; сбой сети — «Нет связи с сервером» |
| К10 | Низко | Фокус в окне импорта был невидим | Видимая рамка у области выбора файла |
| К11 | Низко | Предел файла в 25 МБ не проверялся заранее, ответ — «Слишком большой запрос» или «Ошибка 413» | Размер проверяется до загрузки, сообщение называет предел; в ADR — 25 МБ |
| К12 | Низко | Удаление строки-предшественника не пересчитывало её последователей | Последователи пересчитываются по оставшимся связям, отмена — одна |
| К13 | Низко | Фильтр «Срыв крайнего срока» не находил вехи, хотя статистика их считала | Вехи учитываются в фильтре и в счётчике |
| К14 | Низко | Обновление плана разового переноса молча делало его мастер-копией | Способ ведения выбирается и при обновлении; по умолчанию — текущий способ плана |
| К15 | Низко | Строка, добавленная в мастер-копию в «Пульсе», получала номер, совпадающий с кодом WBS из файла | Такие строки не нумеруются: номера мастер-копии — только коды из файла |
| К16 | Низко | Номер строки не искался и не показывался в подсказке; в карточке не было видно, какие поля придут из файла | Поиск «2.3» находит строку и вложенные; номер — в подсказке полосы; карточка строки мастер-копии называет поля, которые ведутся в MS Project |
| К17 | Низко | Задача в рабочих днях при сдвиге по связи теряла длительность (5 рабочих дней становились 3) | Сохраняется число рабочих дней по календарю плана |
| К18 | Низко | Подзадачу можно было связать с её же группой — последователь выходил за сроки группы | Такие строки не предлагаются, клиент и сервер отклоняют связь |
| К19 | Низко | Руководство: в карточке — «Предшественник, Тип связи, Лаг», в меню — «Следующая задача» | Раздел «Связи» карточки и «Последующая задача» |
| К20 | Низко | На 390 px обрезались «Мастер-копия в MS…» и значок вкладки; название плана не менялось при выборе другого файла; «Категории из поля» пропадали после неудачной проверки | Короткая подпись с подсказкой, значок не сжимается; название следует за файлом, пока его не правили вручную; поля категорий сохраняются |

Проверено и в порядке: расчёт сроков (правило максимума для FS/SS и FF/SF, ромб и ветвления, отрицательные и
рабочие лаги через выходные и праздники, вехи-последователи, «Начало не ранее», циклы без рекурсии, закреплённые
даты из Jira); запрет повторных связей, циклов и связи с собой, недоступные строки в списке с подсказкой;
связь мышью от края полосы; отмена и повтор четырёх разных правок совпадают с сервером в обе стороны; два браузера
(связь к удаляемой строке, отмена удаления, обновление из файла видно коллеге); наблюдатель не видит правок
связей и пунктов MS Project; подсказка «Зависит от», отметки крайнего срока, статистика, столбец «Предшественники»
в CSV; понятные сообщения на .mpp, текст, JSON, пустой файл, чужой XML и DOCTYPE; вёрстка окна и карточки на 390,
1024 и 1440 px без горизонтальной прокрутки; план на 5000 строк — обработка правки около 100 мс, открытие карточки
около 450 мс.
