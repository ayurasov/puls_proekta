# Release notes — v0.2.1

Ветка `v0.2.1` от `v0.2.0`. Выпуск исправлений и доработок по итогам проверки дизайна и удобства 0.2.0:
работа на телефоне и планшете, защита от случайного удаления, клавиатура, легенда, контраст, склонения,
понятный реестр изменений. **Миграций базы нет**, сессии сохраняются. Обновление — `sudo sh deploy/update.sh
v0.2.1` из `/opt/puls` ([руководство по развёртыванию](../manuals/deployment-guide.md)).

## Телефон и планшет

- Меню на телефоне (до 768 px) — выдвижная панель, как в «По Делу»: кнопка в левом верхнем углу, затемнённый
  фон, страница под меню недоступна для фокуса, Esc и переход по ссылке закрывают меню.
- Карточка строки ниже 1280 px открывается поверх диаграммы, а не сжимает её; на телефоне — на весь экран.
- Главная, заголовок проекта, вкладки планов, панель инструментов (на телефоне — поиск и фильтры отдельной
  строкой, остальное — прокручиваемой) и таблицы администрирования помещаются на 390 и 1024 px; цели касания —
  не меньше 40 px.
- Боковое меню — 232 px, как в «По Делу»; уведомления — справа сверху.

## Защита от ошибок

- «План в корзине» и «Проект в корзине» — с кнопкой **Отменить**.
- **Удалить** в меню вкладки плана (при полном управлении): открытый план уходит в корзину сразу, если в
  проекте остаётся другой открытый план, — без обхода через архив.
- Менеджеры видят **Корзину** с удалёнными планами своих проектов и возвращают их; удалить навсегда — только
  администратор.
- В окнах удаления фокус на **Отмене**; смена роли в таблице сотрудников — с отменой из уведомления, выдача и
  снятие роли администратора — с подтверждением.
- Несохранённые настройки входа через домен не теряются молча: при уходе — вопрос, при закрытии вкладки —
  предупреждение браузера. Включение входа через домен выбирает режим «Сначала домен, затем пароль системы».
- Если коллега удалил строку, карточка которой открыта, — уведомление «Строку «…» удалил(а) …».

## Диаграмма Ганта

- Клавиши диаграммы срабатывают только на диаграмме: Enter на кнопке нажимает кнопку, стрелки в меню ходят по
  пунктам и не переключают строки, Delete в карточке не удаляет строку. Подсказка по клавишам — кнопка **?** и
  клавиша «?».
- Легенда — одна строка: категории в порядке настроек плана, задачи без категории — одной записью «Без
  категории», вехи — по цветам; не поместившееся — по кнопке **+N**. В выгрузке легенда переносится по строкам.
- Пометка на строке не наезжает на полосу: в строке с пометкой полоса ниже и тоньше.
- Контраст по WCAG AA: подпись на полосе — белая или чёрная, что контрастнее (с учётом бледных полос
  завершённых и заблокированных задач); прогресс — полоской внизу полосы; статусы и сдвиги в строках, подписи
  пометок и вех — тёмными оттенками.
- Ширина колонки названий по умолчанию зависит от экрана; двойной щелчок по границе — по самому длинному
  названию.
- Строка быстрого добавления добавляет задачу в конец плана; **+ Задача** и Insert — после выбранной строки.
- Карточка строки: статус одним переключателем; сроки — один блок «по дате / по длительности» без повторов
  «Окончание / Дата окончания»; Esc в поле возвращает прежнее значение; поиск в списках предшественника,
  родителя и привязки пометки в больших планах; дата завершения не раньше начала задачи.
- Исполнители плана: цвет — из палитры приложения (системный выбор цвета показывал ключи палитры чёрными),
  аватар связанного сотрудника — в цвете исполнителя.
- Баннер архивного плана называет план, кнопка «Архив» подсвечена; баннер просмотра версии называет версию.
- Копия плана переносит комментарии строк с ответами.

## Проекты

- Карточка проекта считает задачи **основного плана** (первой открытой вкладки), процент — средний прогресс
  задач, как «Средний прогресс» в «Статистике»; подсказка называет план. Копии больше не удваивают задачи.
- Поиск без результатов — «Ничего не найдено» и «Найдено 0 из N проектов».
- Подпись даты на карточке — «Изменён …».

## Администрирование

- Реестр изменений: ФИО авторов, объекты названиями («Проект «…»», «План «…»», «Сотрудник …», «Направление
  «…»»), русские названия разделов («Планы», «Сотрудники»), полей и значений, даты календаря по-русски, фото
  1.0.x — «фото обновлено». Записи, перенесённые из 1.0.1, не переписаны — переводятся при показе. Таблица
  помещается в ширину страницы, длинные значения переносятся. CSV — с теми же подписями и столбцом «Логин».
- Страницы администрирования одной ширины; «Доступы» не шире окна; направления — Enter сохраняет, Esc
  отменяет, строка в правке не перетаскивается, видно место вставки.

## Тексты

- Склонения с числами везде («1 строка», «2 строки», «1 заблокирована», «3 изменения ждут отправки»).
- Единые термины: «Исполнитель» (поле строки и список исполнителей плана), «Пунктирная / Сплошная /
  Точечная», «д» в компактных подписях и «дн.» в текстах, «Комментарий к задаче «…»», «Настройки →
  Производственный календарь»; записи истории из прежней версии помечены «до переноса».
- Окно «Что нового» (номер версии внизу бокового меню) — история версий из `docs/versions.md`.

## Сервер и надёжность

- SQLite: `lock_plan` открывает `BEGIN IMMEDIATE`, одновременные пакеты одного плана выстраиваются в очередь,
  как в PostgreSQL; тест с настоящими потоками проходит на обеих базах ([ADR-0002](../architecture/adr-0002-data-model-and-concurrency.md)).
- API: `stats.progress / planId / planTitle` у проектов, удаление открытого плана, `GET /api/trash` для
  неадминистраторов (только планы с полным управлением, `canPurge`), подписи реестра (`*Label`, `userLogin`,
  `facets.*Labels`).

## Совместимость

- Миграций базы и новых переменных окружения нет; откат на 0.2.0 — прежней командой `deploy/update.sh v0.2.0`
  без восстановления копии.
- Интерфейс API расширен без изменения прежних полей; удаление открытого плана раньше отвечало `409
  not_archived`, теперь выполняется (или `400 last_plan` для единственного открытого плана).
