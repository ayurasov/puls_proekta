# Release notes — v0.7.2

Ветка `v0.7.2` от `v0.7.1`. Состояние системы одной страницей и полномочия без роли администратора. Миграция
`0008_user_capabilities` добавляет столбец полномочий сотрудника. Обновление — `sudo sh deploy/update.sh v0.7.2`
из каталога установки.

## Зачем

- Проверки `/api/health/*` отвечают контейнерам, но не людям: о том, что ночная копия не прошла, схема базы
  отстала после обновления или Jira перестала принимать токен, узнавали от сотрудников. В burndown_tool для этого
  есть «Состояние системы» — сделано так же.
- Администрирование было доступно только роли «Администратор»: кадровику, службе поддержки и дежурному инженеру
  приходилось выдавать доступ ко всем проектам и настройкам. В «По Делу» это решено точечными полномочиями —
  сделано так же и расширено: состояние системы, модули, календарь, реестр, доступы, корзина.

## Что нового

### Состояние системы (ADR-0014)

**Администрирование → Состояние системы** — администратору всегда, остальным — с полномочием «Смотрит состояние
системы». Итог («Всё работает», «Есть замечания», «Есть неполадки») и десять карточек:

| Карточка | Неполадка или замечание, если |
| --- | --- |
| Приложение | схема базы отстаёт от версии приложения; база отвечает дольше 0,5 с; мало места на диске (SQLite) |
| Резервные копии | копии нет больше суток (замечание) или двух суток, последняя копия не удалась |
| Ошибки сервера | были ошибки 500 за сутки (замечание), 20 и больше за час |
| Jira, «По Делу», вход через домен | последнее обращение не удалось: нет связи, отклонён пароль или токен, ошибка сервера |
| Ключи доступа | — (когда каждая система обращалась последний раз) |
| Производственный календарь | нет праздников на текущий год или, с октября, на следующий |
| Сотрудники и вход, данные | — (сводка; совет назначить второго администратора) |

- **Проверить подключения** — обращение к Jira, «По Делу» и каталогу сохранёнными настройками сразу; итог каждой
  проверки — над карточками.
- Точка у пункта меню: жёлтая — замечания, красная — неполадки. Страница обновляется раз в минуту.
- Итог каждой резервной копии записывает контейнер `backup` (`deploy/backup.sh`).

### Полномочия без роли администратора (ADR-0013)

**Сотрудники → ✎ → Полномочия без роли администратора** — только у администратора:

| Полномочие | Открывает |
| --- | --- |
| Смотрит состояние системы | «Состояние системы», проверка подключений |
| Настраивает модули | Jira и «По Делу»: подключение, проверка, поля сроков, ссылки из задач |
| Ведёт производственный календарь | Праздники, переносы, рабочие субботы |
| Смотрит реестр изменений | Реестр и выгрузка CSV |
| Ведёт учётные записи | Сотрудники: создание, роли (кроме администратора), пароли, фото, отключение; импорт и экспорт сотрудников |
| Ведёт структуру компании | Подразделения, руководители, перевод сотрудников, импорт и экспорт структуры |
| Выдаёт доступы к проектам | Доступы сотрудников и подразделений, направления |
| Управляет корзиной | Удаление проектов, корзина всех проектов |

- Сотрудник видит в меню только свои разделы, свои полномочия — в профиле, и читает руководство администратора.
- Только администратору: роль «Администратор», выдача полномочий, ключи доступа, вход через домен.
- «Ведёт учётные записи» не меняет учётные записи администраторов и сотрудников с полномочиями, которых нет у него
  самого, — в том числе импортом; свои роль и вход тоже не меняет.
- Синхронизация с AD и загрузка из «По Делу» меняют и структуру, и учётные записи — нужны оба полномочия.
- В таблице сотрудников — число полномочий у строки и фильтр «С полномочиями»; выдача — в реестре изменений.

## Совместимость

- `/api/auth/me` и `/api/users` — новое поле `capabilities`; прежние поля не менялись.
- Права существующих сотрудников не меняются: у всех список полномочий пуст.
- Email сотрудников в выгрузке MS Project — администратору и «Ведёт учётные записи» (было — только
  администратору).

## Проверка

Сервер — 441 тест (SQLite и PostgreSQL 16), клиент — 292 модульных теста, e2e — 91 сценарий. Миграция `0008`
проверена на PostgreSQL 16 вперёд и назад, `deploy/backup.sh` — на PostgreSQL 16: удачная копия и неудача
`pg_dump` записываются в базу, время последней удачной копии сохраняется.

- Сервер: выдача полномочий и запись в реестр; каждое полномочие открывает свой раздел и только его; ключи доступа
  и вход через домен — администратору; «Ведёт учётные записи» — без роли «Администратор», без учётных записей
  администраторов и сотрудников с чужими полномочиями (и в импорте); «Ведёт структуру компании» — только поля
  структуры; синхронизации — с обоими полномочиями; корзина всех проектов; у отключённого — без полномочий.
  Состояние системы: доступ, карточки без подключений, сбой и восстановление Jira, запись удачных обращений не чаще
  раза в минуту, ошибки сервера, итог копии (свежая, старая, неудачная), схема базы, календарь на следующий год.
- Клиент: тот же список полномочий, что на сервере; разделы меню; защита учётных записей; группы.
- e2e: сводка и карточки, проверка подключений; выдача полномочий в карточке; сотрудник с полномочиями видит только
  свои разделы и вкладки, `/admin` открывает его первый раздел, чужой раздел недоступен, учётная запись
  администратора защищена, полномочия в профиле.
