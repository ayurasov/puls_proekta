# Release notes — v0.6.0

Ветка `v0.6.0` от `v0.5.1`. Ключи интеграций для нескольких систем: у «По Делу» и «Дашбордов компании» свои ключи и
права, показатели проектов для сводных отчётов, ограничение частоты по ключу. Миграция `0006_integration_keys`
добавляет таблицу и переносит в неё ключ «По Делу». Обновление — `sudo sh deploy/update.sh v0.6.0` из каталога
установки.

## Зачем

API интеграций (`/api/integration/v1`) принимал один ключ — ключ «Пульса» для «По Делу»: выпустить ключ ещё одной
системе значило отозвать ключ «По Делу». «Дашбордам компании» для сквозного отчёта по проектам нужны прогресс,
просрочки, задачи в работе и заблокированные, ближайшая веха и направление проекта — без своего ключа им пришлось бы
входить сервисной учётной записью.

## Что нового

- **Интеграции → Ключи доступа**: ключи систем — «По Делу», «Дашборды компании», другие. У каждого ключа права,
  первые символы, кто и когда выпустил, когда система обращалась последний раз; **Права**, **Перевыпустить**,
  **Отозвать**, список отозванных и журнал действий с ключами.
- **Права**: «Проекты и планы» (`projects.read`) — то, что получает «По Делу»; «Показатели проектов»
  (`projects.stats`) — ещё задачи в работе и заблокированные, направление с идентификатором (`directionInfo`), время
  последнего изменения (`updatedAt`), окно плана (`planWindow`).
- `GET /api/integration/v1/directions` — направления с числом видимых проектов.
- Ограничение частоты — 120 запросов в минуту на ключ (было — на адрес); запросы без действующего ключа
  ограничиваются по адресу.

## «По Делу» продолжает работать

Ключ «По Делу» перенесён в таблицу ключей без замены: тот же ключ, право «Проекты и планы», прежние поля ответа.
Страница «Интеграции → «По Делу»» управляет им как раньше; он виден и в «Ключах доступа».

## Как подключить «Дашборды компании»

«Интеграции → Ключи доступа → Выпустить ключ» → система «Дашборды компании» (оба права выбраны) → **Выпустить** →
скопируйте ключ и введите его в настройках «Дашбордов». Проверка: `GET /api/integration/v1/ping` с заголовком
`Authorization: Bearer puls_…` возвращает название ключа и его права.

## Проверка

Сервер — 203 теста (SQLite и PostgreSQL в CI), клиент — 221 модульный тест, e2e — 75 сценариев.

- Сервер: выпуск, перевыпуск, изменение и отзыв ключей с записями реестра; проверка прав на каждом эндпоинте
  (`insufficient_scope`); поля `projects.stats` и неизменные поля ключа «По Делу»; направления по правам сотрудника;
  отметка использования не чаще раза в минуту; счётчик частоты на ключ и общий счётчик адреса для неверных ключей;
  миграция `0006` — перенос ключа «По Делу» и откат; прежние тесты «По Делу» без изменений поведения.
- Клиент: правила прав (показатели только вместе с проектами), подписи, порядок ключей.
- e2e: ключ «По Делу» со своей страницы виден среди ключей и отдаёт прежние поля; ключ «Дашбордов» получает
  показатели и направления; перевыпуск, права, отзыв и журнал.
