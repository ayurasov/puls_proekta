# Release notes — v0.5.1

Ветка `v0.5.1` от `main` (0.5.0). Связь с «По Делу», когда обе системы на одной машине. Миграций базы нет.
Обновление — `sudo sh deploy/update.sh v0.5.1` из каталога установки. Парный выпуск «По Делу» — 1.4.2: в нём то же
поле для обратной стороны связи.

## Почему «ключи выданы, адреса указаны, а проверка связи не проходит»

Проверку связи выполняет не браузер администратора, а backend «Пульса» — процесс в своём контейнере Docker. Адрес,
который открывают сотрудники, ему часто не подходит:

- `http://localhost:39665` или `http://127.0.0.1:39665` — внутри контейнера это сам контейнер «Пульса», а не машина:
  подключение отклоняется;
- имя, прописанное только в `/etc/hosts` машины (`http://podelu.local`), контейнер не видит — имя не находится;
- порт, опубликованный только на `127.0.0.1`, из контейнеров не виден ни по какому адресу.

Проверка в 0.5.0 сообщала одно и то же — «Не удалось подключиться … проверьте адрес и доступность сети». Сами
ключи и обмен ими работали: с адресом, видимым из контейнера (IP машины), проверка проходит в обе стороны — это
воспроизведено на двух стеках Docker Compose на одной машине.

## Что изменилось

- **Адрес для запросов сервера** — необязательное поле в обоих блоках «Интеграции → «По Делу»»: «Ссылки из задач»
  и «Структура и сотрудники». Запросы сервера идут на него, ссылки для сотрудников — на «Адрес «По Делу»». Для двух
  систем на одной машине — `http://host.docker.internal:39665` (или IP машины).
- `host.docker.internal` ведёт из контейнера на машину: в `docker-compose.yml` у backend добавлено
  `extra_hosts: host.docker.internal:host-gateway`.
- **Понятные ошибки**: «адрес — localhost: для сервера «Пульса» это он сам», «не находит имя … /etc/hosts»,
  «отклонил подключение: порт закрыт или опубликован только на 127.0.0.1», «не ответила вовремя — межсетевой экран,
  NO_PROXY» — с подсказкой, что указать. Если ошибка указывает на адрес для запросов сервера, поле раскрывается само.
- Результат проверки показывает, куда обращался сервер («Запрос сервера: …»).
- Ключ и пароль уходят только на те адреса, для которых введены: после смены адреса для запросов сервера их нужно
  ввести заново.

## Как настроить

| Где | Адрес (для сотрудников) | Адрес для запросов сервера |
| ---------------------------------- | -------------------------------- | -------------------------------------- |
| «Пульс»: Интеграции → «По Делу» | `https://podelu.company.ru` или `http://<IP машины>:39665` | `http://host.docker.internal:39665` |
| «По Делу» 1.4.2: Настройки → Интеграции → «Пульс проекта» | `https://puls.company.ru` или `http://<IP машины>:39663` | `http://host.docker.internal:39663` |

Затем ввести ключи заново и «Проверить связь» в обеих системах. Порты обеих систем должны быть опубликованы не только
на 127.0.0.1 (по умолчанию — 0.0.0.0), межсетевой экран — пропускать подключения из сетей Docker
(172.16.0.0/12), а адрес — быть в `NO_PROXY`, если задан `HTTPS_PROXY`. Подробно — руководство по развёртыванию,
«Рядом с другими системами на одной машине», пункт 4.

## Проверка

Сервер — 195 тестов (SQLite и PostgreSQL в CI), клиент — 218 модульных тестов, e2e — 72 сценария.

- Сервер: запросы проверки и задач — на адрес для запросов сервера, ссылки на задачи и `GET /api/podelu/links` — на
  адрес для сотрудников; вход в «По Делу» с `Origin` адреса запросов; повторный ввод ключа и пароля при смене адреса;
  совпадающий адрес не хранится; неверный адрес и адрес без основного отклоняются; ошибки: закрытый порт localhost,
  несуществующее имя, отказ подключения.
- Клиент: нормализация адресов, когда сохранённые ключ и пароль уходят без повторного ввода, когда поле раскрывается.
- Стенд: «Пульс» 0.5.1 и «По Делу» 1.4.2 в Docker Compose на одной машине — обмен ключами и проверка связи в обе
  стороны через `host.docker.internal`, с адресами для сотрудников `http://localhost:…`.
