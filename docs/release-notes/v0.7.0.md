# Release notes — v0.7.0

Ветка `v0.7.0` от `v0.6.1`. Первый выпуск по [ADR-0012](../architecture/adr-0012-ms-project.md): графики из MS
Project переносятся в «Пульс» без ручного набора, а модель связей становится как в MS Project. Миграция
`0007_plan_links` переносит связи строк в отдельную таблицу без потери данных. Обновление — `sudo sh
deploy/update.sh v0.7.0`.

## MS Project

- **Загрузка файла MS Project XML** (в MS Project: «Файл → Сохранить как → XML (*.xml)»): новым проектом (**Из MS
  Project** на главной), новым планом проекта («+» в строке вкладок), заменой содержимого плана и обновлением
  плана (меню вкладки).
- **Два способа работы**, выбираются при загрузке:
  - **разовый перенос** — план дальше ведётся в «Пульсе»;
  - **мастер-копия** — график ведётся в MS Project, «Пульс» обновляется из сохранённого файла. Строки
    сопоставляются по идентификаторам задач MS Project; обновляются названия, структура, сроки, связи, прогресс,
    исполнители и крайние сроки, а комментарии, пометки, ссылки Jira, цвета и строки, добавленные в «Пульсе»,
    сохраняются. У такого плана на вкладке — значок **MS Project**, номера строк — коды WBS из файла.
- **План загрузки** до записи: сколько будет групп, задач, вех, связей и исполнителей (и сколько связано с
  сотрудниками), что учесть (связи суммарных задач, материальные ресурсы, неактивные задачи и т. п.), строки
  первых уровней; при обновлении — изменения по полям «было → стало», новые строки и строки, которых нет в файле.
  Параметры — длительности по датам файла или в рабочих днях, сроки текущие или по базовому плану (отставание —
  сдвигом), категории из настраиваемого поля.
- Применение — одной операцией, без ограничения размера плана (проверено на 5000 задачах), перед заменой и
  обновлением — версия «До импорта». Файл не хранится на сервере.
- **Экспорт → MS Project (XML)**: группы — суммарными задачами, задачи и вехи, все связи с лагами, исполнители —
  ресурсами, крайние сроки и ограничения, комментарии — заметками, производственный календарь — исключениями
  календаря проекта. Задачи, пришедшие из MS Project, сохраняют свои идентификаторы.

## Связи, сроки и номера

- **Несколько предшественников** у задачи и **вехи-последующие**. Связи — в разделе «Связи» карточки (тип, лаг,
  календарные или рабочие дни) или мышью от кружка у конца полосы. Задача начинается после самого позднего из
  предшественников (связи на начало) и заканчивается не раньше самого позднего (связи на окончание);
  длительность сохраняется. Связь, замыкающая цикл, не создаётся — карточка объясняет почему.
- **Крайний срок** — маркер ▼ над полосой, красный при срыве; фильтр «Срыв крайнего срока» и строка в статистике.
- **Начало не ранее** — автосдвиг не ставит задачу раньше даты. Другие ограничения из MS Project показываются для
  сведения.
- **Номер (1.2.3)** — нумерация строк по структуре в «Вид → Колонки слева»; в CSV — «№», «Крайний срок» и
  «Предшественники».

## Обновление

- Миграция `0007_plan_links`: связь каждой строки (в том числе удалённой) переносится в таблицу связей; прежние
  столбцы остаются до следующего выпуска; откат возвращает первую связь строки.
- Откройте заново страницы планов, открытые до обновления (F5).

## Проверка

- Сервер — 414 тестов: связи (операции, циклы, восстановление строк, снимки, копия, перенос 1.0.1, миграция вверх
  и вниз на SQLite и PostgreSQL), MS Project — 190 тестов (каждое правило сопоставления, совпадение с расчётом
  «Пульса», план обновления, запись в порядке схемы, круговой обход, защита от небезопасного XML, 5000 задач),
  API импорта для всех четырёх назначений.
- Клиент — 279 тестов: автосдвиг по нескольким связям, рабочие лаги, вехи, «не ранее», отмена связей, большие
  правки частями, номера строк.
- e2e — 88 из 88: связи в карточке и мышью, крайний срок, проект из MS Project как мастер-копия, обновление из изменённого
  файла с сохранением комментария, выгрузка в MS Project XML.

Независимые проверки сервера и клиента и что по ним исправлено — [отчёт](../review/v0.7.0-independent-checks.md).
