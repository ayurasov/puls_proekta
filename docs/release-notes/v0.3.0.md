# Release notes — v0.3.0

Ветка `v0.3.0` от `v0.2.1`. «Пульс Проекта» связывается с Jira по задачам строк плана
([ADR-0007](../architecture/adr-0007-jira-integration.md)), получает структуру компании, общую с «По Делу»
([ADR-0008](../architecture/adr-0008-company-structure.md)), доступ к проектам для подразделений и руководства
прямо в приложении. Обновление с 0.2.x — `sh deploy/update.sh v0.3.0`; миграции только добавляют таблицы и столбцы.

## Jira

- **Подключение** — «Администрирование → Интеграции», как в burndown_tool: Jira Server/DC (логин и пароль или
  Personal Access Token) или Jira Cloud (email и API-токен), «Не проверять TLS-сертификат», поля дат начала и срока
  (список загружается из Jira), «Проверить подключение». Пароль хранится зашифрованным и не возвращается в интерфейс;
  сохранённый пароль уходит только на тот адрес, для которого введён.
- **Строка плана ↔ задача Jira.** В карточке задачи — ключ `ABC-123` или ссылка. Карточка показывает статус,
  исполнителя, начало, срок, дату решения, трудозатраты и прогресс; что в Jira иначе — переносится по полю или целиком.
- **Сверка с Jira** — все строки плана, которые расходятся с Jira, с выбором полей и строк; одна отменяемая правка.
- **Задачи из Jira** — новые строки по ключам или запросу JQL (до 200), в конец плана или в группу; одна правка.
- **На графике** — статус Jira под названием строки, в подсказке над полосой, в колонке «Jira»; значок ссылки
  на полосе окрашен по категории статуса.
- **Надёжность.** Данные задач кэшируются на 5 минут, Jira получает один пакетный запрос на план. Если Jira
  недоступна, план открывается с сохранёнными данными, а сервер минуту не обращается к ней. «Пульс» в Jira не пишет.

| В Jira | В строке плана |
| --- | --- |
| Тема | Название |
| Категория статуса «К выполнению» / «В работе» / «Готово» | Новая / В работе (кроме «Заблокирована») / Завершена с датой решения |
| Начало и срок | Начало и окончание (если есть и начало не позже срока) |
| Затрачено и осталось | Прогресс |

## Структура компании

- **Модель «По Делу»**: подразделения с типами (компания, дирекция, направление, служба, отдел, сектор, группа,
  позиция) и порядком, несколько руководителей с основным, подразделение и явный руководитель сотрудника, «первое
  лицо». Руководитель сотрудника вычисляется так же, как в «По Делу»; циклы подчинения запрещены.
- **«Структура компании»** в главном меню для всех: дерево подразделений с поиском по подразделениям и людям,
  карточки подразделения и сотрудника (руководитель и откуда он, цепочка подчинения, подчинённые), ссылки на них.
- **Администрирование**: «Структура» — подразделения, руководители, типы и глубина; «Сотрудники» — подразделение и
  руководитель в карточке, фильтр по подразделению.
- **Импорт и экспорт** в форматах «По Делу» — файл из одного инструмента загружается в другой:
  `podelu.org-structure` (структура, типы, руководители), `podelu.employees` (сотрудники: CSV, JSON, ZIP с фото),
  быстрый CSV «люди + подразделения», синхронизация с Active Directory по подключению «Вход через домен»; то же из
  командной строки (`scripts/org_transfer.py`), синхронизацию с AD можно запускать по расписанию. Каждая загрузка
  сначала проверяется и показывает план, затем применяется одной транзакцией; коллизии решает администратор.

## Доступ подразделениям

- В «Доступах» доступ к проекту или направлению выдаётся подразделению: его получают сотрудники подразделения и
  всех вложенных, включая будущих. Перешедший в другое подразделение сотрудник теряет доступ прежнего.
- Итог — наибольший уровень из правил сотрудника, его подразделения и вышестоящих, направлений и авторства проекта,
  с учётом роли. Матрица «Кто что видит» учитывает правила подразделений.

## Руководства в приложении

- **Руководство** в боковом меню: руководство пользователя (`/guide`), администраторам — и руководство
  администратора (`/guide/admin`). Оглавление, поиск с подсветкой, ссылки на разделы, увеличение снимков,
  «Открыть PDF», «Скачать PDF», «Скачать DOCX». Текст — те же файлы, что для DOCX и PDF.
- **«?»** на панели плана, в карточке строки, окнах плана, разделах администрирования и новых экранах открывает
  нужный раздел руководства.

## Проверка

- Сервер: 123 теста (SQLite и PostgreSQL в CI), в том числе Jira на заглушке, правила структуры и доступа
  подразделений, форматы обмена на настоящих выгрузках todo-planner 1.4, синхронизация с AD на тестовом каталоге.
- Клиент: 121 модульный тест (правила переноса из Jira, разборщик Markdown и безопасность, ZIP, импорт CSV).
- e2e: 46 сценариев — наборы Jira, импорта и экспорта структуры, структуры и доступа подразделений, руководств, вместе с
  прежними сценариями на перенесённой базе 1.0.1.

Независимые проверки клиента и сервера и что по ним исправлено — [отчёт](../review/v0.3.0-independent-checks.md).

## Известные ограничения

- «Пульс» только читает Jira: сроки из плана в Jira не переносятся.
- Замещения, функциональное подчинение и видимость по структуре — понятия «По Делу», в «Пульсе» не используются;
  при загрузке файлов «По Делу» эти поля пропускаются с пояснением.
