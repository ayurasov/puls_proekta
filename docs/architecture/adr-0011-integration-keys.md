# ADR-0011. Ключи интеграций: несколько систем, права и ограничение частоты по ключу

- Статус: принято
- Дата: 2026-11-01
- Версия: 0.6.0
- Связано: ADR-0004 (доступы), ADR-0010 (ссылки из задач «По Делу»), dashboards_serv ADR-0010 (сквозные отчёты)

## Контекст

В 0.5.x `/api/integration/v1` принимал один ключ — ключ «Пульса» для «По Делу», хранившийся в
`app_settings['podelu_links'].inbound`. Выпуск нового ключа отзывал ключ «По Делу». «Дашбордам компании» для
сквозного отчёта нужны проекты «Пульса» с показателями (прогресс, просрочки, задачи в работе и заблокированные,
ближайшая веха, направление); без своего ключа им пришлось бы входить сервисной учётной записью через сессию и
CSRF. Ограничение частоты считалось по адресу, поэтому две системы за одним прокси делили бы один счётчик.

## Решение

### Таблица ключей

`integration_keys`: `name`, `app` (`podelu`, `dashboards`, `other`), `scopes` (JSON-список), `key_hash` (SHA-256,
уникальный), `prefix` (первые 12 символов), `issued_at`/`issued_by_id`, `last_used_at`, `revoked_at`/`revoked_by_id`.

- Ключ — `puls_` + `secrets.token_urlsafe(32)`, показывается один раз. Поиск — по уникальному отпечатку одним
  запросом, затем `hmac.compare_digest`.
- **Перевыпуск** меняет отпечаток той же записи (название, система и права сохраняются), прежний ключ перестаёт
  действовать сразу. **Отзыв** — `revoked_at`; запись остаётся для истории.
- `last_used_at` пишется не чаще раза в минуту.
- Миграция `0006_integration_keys` переносит ключ «По Делу» из настройки в таблицу (`app = podelu`,
  `scopes = [projects.read]`, те же отпечаток, первые символы и даты) и убирает его из настройки; «По Делу»
  продолжает работать с тем же ключом. Откат возвращает действующий ключ «По Делу» в настройку.
- Страница «По Делу» управляет этим же ключом: «Выпустить новый» — перевыпуск, «Отозвать» — отзыв.

### Права (scopes)

| Право | Эндпоинты и поля |
| --- | --- |
| `projects.read` | `projects`, `projects/<id>`, `projects/<id>/items`, `directions` — поля 0.5.x без изменений |
| `projects.stats` | в `projects` и `projects/<id>` ещё `inwork`, `blocked`, `directionInfo {id, name}`, `updatedAt`, `planWindow {start, end}` |

- `projects.stats` выдаётся только вместе с `projects.read` (сервер добавляет его сам).
- `ping` — любому действующему ключу; ответ называет ключ и его права.
- Нет права — `403 insufficient_scope`; нет действующего ключа — `401 unauthorized`.
- **Прежние поля не меняются.** Направление строкой остаётся в `direction` — на нём держится «По Делу»; объект
  `{id, name}` приходит отдельным полем `directionInfo`, а не заменяет `direction`. Так ключу «По Делу» можно
  выдать `projects.stats`, не ломая его разбор ответа.
- `updatedAt` — позднее из изменения проекта и его основного плана; `planWindow` — шкала основного плана
  (`settings.range`); `inwork`, `blocked`, `overdue`, `progress` — по задачам основного плана, как на карточке
  проекта и в статистике «Пульса».

`GET /api/integration/v1/directions?userId=&login=&email=` — направления с числом проектов, которые видит
сотрудник (направление без доступных ему проектов не показывается, как на главной «Пульса»), и
`withoutDirection`; без контекста сотрудника — все направления.

### Ограничение частоты

120 запросов в минуту **на ключ**: счётчик — `integration-key:<id>`. Запросы без действующего ключа считаются по
адресу (`integration-ip:<адрес>`): подбор ключа не получает нового счётчика на каждую попытку. Ключ ищется один раз
на запрос — для ограничения частоты и для проверки прав.

### Администрирование

«Интеграции → Ключи доступа»: список действующих и отозванных ключей, выпуск (система, название, права), права,
перевыпуск, отзыв. Каждое действие — запись реестра изменений (раздел «Интеграции», без самого ключа); журнал
этих записей — на той же странице. `GET|POST /api/settings/integration-keys`,
`POST /api/settings/integration-keys/<id>/reissue`, `PATCH|DELETE /api/settings/integration-keys/<id>` — только
администратору.

## Последствия

- Каждая система получает только нужные ей данные и отключается независимо; ключ «По Делу» больше не зависит от
  ключей других систем.
- «Дашборды компании» читают проекты по ключу, без учётной записи и сессии.
- Новые системы — новая запись `app` и, при необходимости, новое право; прежние поля ответа не меняются.
