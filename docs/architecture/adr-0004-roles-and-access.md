# ADR-0004. Роли и доступы

- Статус: принято
- Дата: 2026-10-30
- Версия: 0.2.0
- Связано: ADR-0002 (модель данных), ADR-0003 (безопасность)

## Контекст

В 1.0.1 были роли «Администратор», «Менеджер», «Редактор», «Наблюдатель» и правила доступа «сотрудник →
проект или группа проектов, уровень». На практике:

- роль «Наблюдатель» не ограничивала ничего — наблюдатель с правилом «редактирование» правил план;
- повторная выдача доступа создавала дубли правил (в production-базе — 3 пары);
- проверки прав частично выполнялись в браузере.

## Решение

### Роли

| Роль | Что может |
| --- | --- |
| Администратор | Всё: все проекты с полным управлением, сотрудники, направления, доступы, реестр, корзина, настройки |
| Менеджер | Создаёт проекты и направления; полностью управляет **своими** проектами; к остальным — по правилам доступа |
| Редактор | Работает в проектах по выданным доступам |
| Наблюдатель | Только просмотр: уровень доступа ограничивается «просмотром», даже если выдано больше |

### Уровни доступа к проекту

| Уровень | Что можно |
| --- | --- |
| Просмотр | Смотреть планы, историю и версии, фильтровать, выгружать |
| Редактирование | Плюс: править строки, пометки, исполнителей, настройки графика, создавать и архивировать планы, комментировать |
| Полное управление | Плюс: переименовывать проект, удалять архивные планы в корзину |

Удалять проекты и очищать корзину может только администратор.

### Правила

- Правило — «сотрудник → проект» или «сотрудник → направление» (все проекты направления, включая будущие)
  с уровнем. Действующий уровень — наибольший из правил; затем ограничение роли.
- Уникальность — частичные уникальные индексы (`user_id, project_id`) и (`user_id, direction_id`):
  дубль невозможен. Массовая выдача (сотрудники × проекты/направления) в режиме «заменить уровень» или
  «только повысить»; повторная выдача не создаёт дублей.
- «Кто что видит» — матрица действующих уровней сотрудников по проектам с учётом ролей и направлений.
- Проверки — на сервере: `security.project_levels` и `accessible_projects_query` (одни правила для списка
  проектов и для каждого запроса к плану).
- Защита от ошибок: нельзя снять роль администратора с последнего активного администратора, отключить или
  удалить себя.

## Последствия

- Роли соответствуют названиям; доступы видны и управляемы на одной странице.
- При переносе 1.0.1 дубли правил объединяются с наибольшим уровнем (отчёт переноса показывает число).
- Наблюдатели, которым в 1.0.1 был выдан уровень «редактирование», после перехода смотрят план, но не правят
  его. Если кому-то нужно править — смените роль на «Редактор» (руководство администратора).
