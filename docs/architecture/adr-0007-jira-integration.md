# ADR-0007. Связь с Jira по задачам строк плана

- Статус: принято
- Дата: 2026-10-30
- Версия: 0.3.0
- Связано: ADR-0002 (операции плана), ADR-0003 (безопасность), ADR-0004 (права)

## Контекст

В 1.0.x у задачи было поле «Ссылка Jira» — просто адрес, который открывался в новой вкладке. Руководитель
проекта сверял статусы и сроки с Jira вручную. В соседнем инструменте burndown_tool связь с Jira уже есть:
одно подключение на систему, его настраивает администратор, токен хранится зашифрованным, запросы идут только
на указанный адрес. Инструменты в перспективе связываются между собой, поэтому подключение и его правила должны
быть одинаковыми.

## Решение

### Подключение

Как в burndown_tool (и jira_mass_logger): одно подключение на систему, раздел «Администрирование → Интеграции».

| Способ входа | Аутентификация | API |
| --- | --- | --- |
| Jira Server/DC — логин и пароль | Basic (логин и пароль в UTF-8) | REST v2 |
| Jira Server/DC — Personal Access Token | Bearer | REST v2 |
| Jira Cloud — email и API-токен | Basic | REST v3 (`search/jql`, `nextPageToken`) |

- Пароль или токен шифруется (Fernet, ключ выводится из `SECRET_KEY`) и в интерфейс не возвращается. Сохранённый
  токен уходит только на тот адрес, для которого был введён: смена адреса требует ввести токен заново.
- Адрес — только `http(s)://хост[:порт][/путь]`, без логина, `?` и `#`; `JIRA_ALLOWED_HOSTS` ограничивает хосты.
  Перенаправления не выполняются (токен не уходит на чужой адрес), повтор при 429/503 с учётом `Retry-After`,
  таймауты 5 с на подключение и 20 с на ответ, прокси — из окружения сервера.
- Сотрудники без прав администратора получают ошибки без адреса Jira и технических подробностей.
- Поля дат настраиваются: «срок» (по умолчанию стандартное `duedate`) и необязательное «начало» (например,
  Start date из Advanced Roadmaps); список полей с датой загружается из Jira.

### Задачи строк

- Поле строки «Задача в Jira» хранит ссылку, как в 1.0.x (формат данных не меняется). Ключ задачи определяется из
  ссылки на подключённую Jira: `/browse/ABC-1`, `/issues/ABC-1`, `?selectedIssue=ABC-1`. Ссылки на другие адреса
  остаются просто ссылками. Сотрудник может ввести ключ `ABC-123` — он превращается в ссылку.
- `GET /api/plans/<id>/jira` — данные задач всех строк плана: статус и его категория, исполнитель, тип,
  приоритет, начало, срок, дата решения, трудозатраты и прогресс по ним. Нужен доступ к плану.
- Кэш `jira_issues` на `JIRA_CACHE_SECONDS` (300 с): план открывается без ожидания Jira, Jira получает один
  пакетный запрос `key in (…)` на устаревшие задачи, а не запрос от каждого открывшего план. «Обновить из
  Jira» перечитывает все задачи плана (не чаще 20 раз в минуту на сотрудника).
- Если Jira не ответила, план показывает данные кэша с пометкой, и следующую минуту процесс сервера не
  обращается к Jira при открытии планов — работа с планами не зависит от доступности Jira.
- Если Jira отклоняет пакет из-за несуществующего ключа (Cloud), задачи пакета читаются по одной; удалённые
  и недоступные задачи помечаются «нет в Jira или нет доступа».

### Перенос данных из Jira в план

Данные из Jira в план не попадают сами: сотрудник видит, что отличается, и переносит то, что нужно, — одной
правкой, которая отменяется как любая другая (Ctrl+Z) и записывается в историю плана.

| Jira | Строка плана |
| --- | --- |
| Тема | Название |
| Категория статуса «К выполнению» / «В работе» / «Готово» | Новая / В работе / Завершена (с датой решения и прогрессом 100 %) |
| Поле начала, срок | Начало, окончание (если в Jira есть данные и начало не позже срока) |
| Затрачено / (затрачено + осталось) | Прогресс |

«Заблокирована» не меняется на «В работе»: в Jira блокировка обычно не отдельная категория статуса.

Где это доступно: карточка строки (данные задачи и «Перенести» по полю или всё сразу); «Сверка с Jira» —
все строки плана, которые расходятся, с выбором полей и строк; «Задачи из Jira» — новые строки по ключам или
запросу JQL (до 200), одной правкой; уже привязанные задачи отмечены.

## Последствия

- Учётная запись подключения определяет, какие задачи видны всем сотрудникам с доступом к плану. Рекомендуем
  сервисную учётную запись с правом только просмотра нужных проектов Jira (об этом сказано в форме и в
  руководстве администратора).
- «Пульс» в Jira не пишет: подключение может быть только на чтение. Запись (например, сроков из плана в Jira)
  — возможное развитие, тогда понадобятся права и подтверждение.
- Один формат подключения с burndown_tool: при объединении инструментов подключение переносится как есть.
