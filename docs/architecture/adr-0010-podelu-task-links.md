# ADR-0010. Ссылки из задач «По Делу» на проекты «Пульса»: обмен ключами

- Статус: принято
- Дата: 2026-10-31
- Версия: 0.5.0
- Связано: ADR-0003 (безопасность), ADR-0004 (доступы), ADR-0009 (связь с «По Делу»), todo-planner ADR-0055

## Контекст

Задачи сотрудников ведутся в «По Делу», планы проектов — в «Пульсе». Сотрудникам нужно связывать задачу «По Делу»
с проектом «Пульса» и конкретной строкой плана, а руководителю проекта — видеть в «Пульсе», какие задачи «По Делу»
ведутся по проекту. Подключение из ADR-0009 работает в одну сторону и через сервисную учётную запись с правами
администратора «По Делу»: для постоянной связи двух систем и для запросов «По Делу» к «Пульсу» оно не подходит —
«По Делу» не должна хранить пароль администратора «Пульса», а «Пульс» — ходить в «По Делу» под администратором ради
чтения ссылок. Интеграцию настраивает администратор с каждой стороны; ссылки в задачах доступны только после
проверенной связи.

## Решение

### Ключи

Обмен ключами, как у вебхуков: каждая система выпускает свой ключ, администратор вводит его в другую систему.

| Ключ | Выпускает | Вводится | Для чего |
| --- | --- | --- | --- |
| `puls_…` | «Пульс»: Интеграции → «По Делу» | «По Делу»: Настройки → Интеграции → «Пульс проекта» | «По Делу» ищет проекты и строки планов |
| `podelu_…` | «По Делу» | «Пульс»: Интеграции → «По Делу» | «Пульс» читает задачи, связанные с проектом |

- Формат — префикс и `secrets.token_urlsafe(32)`. Выпускающая сторона хранит SHA-256 ключа (сравнение
  `hmac.compare_digest`), первые 12 символов, дату выпуска и последнего использования (отметка — не чаще раза в
  минуту); ключ показывается один раз. «Выпустить новый» отменяет прежний, «Отозвать» — удаляет.
- Принимающая сторона хранит чужой ключ зашифрованным (в «Пульсе» — Fernet, ключ из `SECRET_KEY` со своей солью
  `podelu-links-key:`), в интерфейс не возвращает и отправляет только на адрес, для которого ключ введён: смена
  адреса требует ввести ключ заново, включение «Не проверять TLS» — тоже.
- Показ задач «По Делу» в «Пульсе» включается только после успешной проверки (`ping` с ключом) — проверка
  запоминает отпечаток пары «адрес + ключ» и сбрасывается при их смене.

### API «Пульса» для «По Делу» — `/api/integration/v1`

Только GET, `Authorization: Bearer puls_…`, без cookie и CSRF (blueprint исключён из CSRF, сессия не читается);
120 запросов в минуту с адреса — ограничение считается до проверки ключа, так что подбор ключа ограничен так же.

- `ping` — имя и версия «Пульса».
- `projects?q=&ids=&limit=` — проекты; `projects/<id>` — с планами; `projects/<id>/items?plan=&q=&key=` — строки
  плана (основного по умолчанию) с путём родительских групп и адресом `…/projects/<id>/<plan>?item=<ключ>`.
- Контекст сотрудника — `userId` (id в «По Делу» = `users.podelu_id`), `login`, `email`: «Пульс» ищет активного
  сотрудника в этом порядке и применяет те же правила доступа, что в интерфейсе (ADR-0004). Сотрудник не найден —
  пустой список и 404 на подробности. Без контекста — все не удалённые проекты: режим «все проекты» администратор
  «По Делу» включает явно.

### API «По Делу» для «Пульса» — `/api/integrations/puls`

`ping`, `projects/<id>/tasks?item=` (задачи со ссылкой на проект или строку, без удалённых), `summary?projects=`
(число задач по проектам). «Пульс» читает их с ключом «По Делу»: ответ проверяется по полям и длинам, ссылка на
задачу собирается только из относительного пути и адреса «По Делу» (`//…` и абсолютные адреса не принимаются),
ответ — не больше 5 МБ, без перенаправлений, таймауты 5 и 15 с.

### Что видно в «Пульсе»

`GET /api/projects/<id>/podelu-tasks` и `GET /api/podelu/links/summary` — только сотрудникам с доступом к проекту.
Видны название, статус, приоритет, исполнитель и срок задачи, кто и когда связал. При привязке «По Делу»
предупреждает: «Название, статус, исполнитель и срок задачи увидят участники проекта в «Пульсе»». Ошибка «По Делу»
сотруднику показывается общими словами, администратору — с причиной.

## Последствия

- Связь двух систем не зависит от паролей сотрудников и учётной записи администратора; любой ключ можно отозвать
  независимо.
- Задачи «По Делу» не копируются в базу «Пульса»: «Пульс» читает их при открытии проекта, поэтому статус всегда
  свежий, а недоступность «По Делу» не ломает план (кнопка показывает предупреждение).
- Для структуры и сотрудников по-прежнему используется подключение ADR-0009; со временем его можно перевести на
  ключи, когда «По Делу» отдаст выгрузки по ключу.
