# ADR-0001. Платформа и стек 0.2

- Статус: принято
- Дата: 2026-10-30
- Версия: 0.2.0
- Связано: ADR-0002 (модель данных), ADR-0003 (сессии и безопасность), ADR-0005 (перенос 1.0.x), ADR-0006 (редактор Ганта)

## Контекст

Версия 1.0.1 («Пульс Проекта» на прежней нумерации) работала в production на одном сервере Ubuntu:

- Node.js + Express + SQLite (better-sqlite3), клиент React; диаграмма Ганта — отдельная страница
  `gantt.html` (≈ 900 КБ одного файла) внутри `iframe`, обмен с приложением через `postMessage`;
- запуск через Python-обёртку `app.py` под gunicorn: она поднимала Node.js подпроцессом и проксировала каждый
  запрос; служба systemd `puls` от имени root, порт 39663;
- в репозитории — только собранные файлы (`dist/`), исходных каталогов `client`, `server`, `shared` нет:
  исправлять и развивать систему было можно только правкой минифицированного кода.

Требования к развитию: надёжность и сохранность данных при обновлениях, работа 1000–2000 сотрудников
(как у todo-planner), в перспективе — интеграция с todo-planner («По Делу»).

## Решение

Построить версию 0.2 заново на стеке todo-planner и не подстраиваться под устройство 1.0.1; данные 1.0.1
переносятся без потерь со сверкой (ADR-0005).

| Слой | Решение |
| --- | --- |
| Сервер | Python 3.12, Flask 3, Flask-SQLAlchemy / SQLAlchemy 2, Alembic, pydantic 2, Flask-WTF (CSRF), Flask-Limiter, bcrypt, ldap3; gunicorn (процессы sync) |
| База | PostgreSQL 16 в production; SQLite для разработки, тестов и e2e |
| Клиент | Vue 3, Pinia, Vue Router, Vite; собственная дизайн-система с токенами todo-planner; jsPDF для PDF |
| Диаграмма Ганта | часть приложения: SVG-рендер, чистые доменные модули с тестами (ADR-0006) |
| Развёртывание | Docker Compose: `db`, `backend`, `frontend` (nginx: SPA и прокси `/api`), `backup`; разовый профиль `migrate` для переноса 1.0.x |
| Качество | ruff, pytest (SQLite и PostgreSQL), eslint, vitest, e2e на Playwright, CI GitHub Actions с репетицией установки в Docker |

Версионирование — как в todo-planner: ветка и версия `vX.Y.Z`; до первого релиза `X = 0`; `Y` — крупная
версия, `Z` — исправления. Источник номера — `version` в корневом `package.json`; backend читает его же
(`app/version.py`), номер виден в меню и в `/api/health/ready`. Прежние 1.0.0 и 1.0.1 по новой нумерации —
0.1.0 и 0.1.1.

## Альтернативы

- **Восстановить исходники 1.0.1 из сборки.** Минифицированный бандл без карт исходников не даёт
  поддерживаемого кода; архитектурные проблемы (один JSON на проект, сохранение целиком, страница в
  `iframe`) остались бы.
- **Оставить SQLite в production.** Для одного сервера и сотни пользователей достаточно, но блокировка всей
  базы на запись, отсутствие сетевого доступа для резервного копирования без остановки и расхождение с
  todo-planner делают SQLite плохой основой для 1000–2000 сотрудников и будущей интеграции.

## Последствия

- Один стек и одни приёмы (сессии, CSRF, роли, развёртывание, документы) с todo-planner: инструменты проще
  интегрировать, сопровождение — одно.
- Обновление — `deploy/update.sh`: резервная копия, новая версия из git, пересборка, миграции Alembic при
  старте, проверка готовности (руководство по развёртыванию).
- Порт 39663 сохранён: адрес системы для сотрудников не меняется.
- Переход с 1.0.1 — разовая процедура со сверкой (runbook `v0.2.0-migration-from-1.0.1.md`); прежняя
  установка остаётся нетронутой для отката.
