# CHANGELOG

## v0.3.0 — 2026-10-30

Связь с Jira по задачам строк плана, структура компании, общая с «По Делу», доступ подразделениям и
руководства в приложении. Подробно: [release notes](docs/release-notes/v0.3.0.md),
[для пользователей](docs/versions.md), [для администраторов](docs/versions_admin.md).

### Сервер

- Jira ([ADR-0007](docs/architecture/adr-0007-jira-integration.md)): подключение в app_settings — Jira Cloud
  (email + API-токен), Server/DC (PAT или логин и пароль), «не проверять TLS», поля дат; токен зашифрован (Fernet из
  `SECRET_KEY`) и уходит только на адрес, для которого введён; проверка адреса, `JIRA_ALLOWED_HOSTS`, без
  перенаправлений, повтор при 429/503. `GET /api/plans/<id>/jira` — задачи строк плана из кэша `jira_issues`
  (`JIRA_CACHE_SECONDS`), `refresh=1` перечитывает; при недоступности Jira — данные кэша и минута без запросов к
  ней. `POST /api/jira/search` — задачи по ключам (через кэш) или JQL. Миграция `0002_jira_issues`.
- Структура компании ([ADR-0008](docs/architecture/adr-0008-company-structure.md)): подразделения (UUID, типы,
  порядок, источник, внешний id), руководители с основным, подразделение и явный руководитель сотрудника,
  «первое лицо»; руководитель по правилам «По Делу», без циклов. `/api/org/tree`, `/api/org/users/<id>`,
  `/api/org/settings`, `/api/departments`. Миграция `0003_org_structure`.
- Доступ подразделению на всю его ветку: `department_access_rules`, учёт в списке проектов, доступе к плану и
  матрице «Кто что видит»; `/api/access/departments`. Миграция `0004_department_access`.
- Импорт и экспорт в форматах «По Делу»: `podelu.org-structure` (`/api/org/export`, `/api/org/import/structure`),
  `podelu.employees` CSV/JSON/ZIP с фото (`/api/users/export`, `/api/users/import`,
  `/api/users/import/avatars`), быстрый CSV (`/api/org/import/csv`), Active Directory (`/api/org/sync/ad`).
  Проверка без записи и применение одной транзакцией; коллизии и совпадение личности решает администратор;
  защита последнего администратора и своей учётной записи; отключённым при импорте — отзыв сессий. Командная
  строка `scripts/org_transfer.py` (в том числе синхронизация с AD по расписанию). Совместимость проверена
  выгрузками todo-planner 1.4 в обе стороны.

### Клиент

- Jira в плане: ключ задачи в карточке строки, карточка задачи Jira с отличиями и переносом по полю или целиком;
  меню **J** — «Обновить из Jira», «Сверка с Jira», «Задачи из Jira» (ключи или JQL); статус Jira под названием,
  в подсказке, в колонке «Jira» и цветом значка на полосе. Всё переносится одной отменяемой правкой
  (`editor.createItems` — несколько строк одной правкой).
- «Администрирование → Интеграции»: подключение к Jira как в burndown_tool.
- «Структура компании» для всех; «Администрирование → Структура» и «Импорт и экспорт»; подразделение и
  руководитель в карточке сотрудника, фильтр по подразделению; «Доступы» — выдача подразделениям.
- Руководства внутри приложения: пункт «Руководство» в боковом меню, `/guide` — руководство пользователя,
  `/guide/admin` — руководство администратора (только администраторам). Оглавление, поиск по тексту разделов
  с подсветкой, ссылки на разделы, увеличение снимков экрана, «Открыть PDF», «Скачать PDF», «Скачать DOCX».
  Текст — те же `docs/manuals/*.md`, что и для DOCX/PDF, через собственный безопасный разборщик Markdown.
- Контекстная справка «?» на панели плана, в карточке строки, окнах плана, разделах администрирования и
  новых экранах; тест следит, чтобы ссылки не устаревали при правке руководств.
- «О программе» — блок «Документация» с обоими руководствами.

### Сборка и развёртывание

- PDF, DOCX и снимки экранов руководств — файлы сборки с хэшем в имени; старая ссылка `/user-guide.pdf` ведёт на
  `/guide`. `.dockerignore` пропускает в образ только нужные приложению файлы руководств.
- Backend: зависимости `requests`, `cryptography`; переменные `JIRA_ALLOWED_HOSTS`, `JIRA_CACHE_SECONDS` и
  прокси `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY` в docker-compose.
- e2e: порты стенда настраиваются (`E2E_API_PORT`, `E2E_WEB_PORT`), vite запускается без npx и не остаётся после
  тестов; новые наборы — Jira с заглушкой, импорт и экспорт структуры, структура и доступ подразделениям,
  руководства.

### Документация

- ADR-0007 (Jira), ADR-0008 (структура компании); руководства пользователя, администратора и по развёртыванию —
  новые разделы и сценарии, снимки экранов.

## v0.2.0 — 2026-10-30

Новая платформа «Пульса Проекта» на стеке todo-planner: сервер Flask + PostgreSQL + Alembic, клиент Vue 3,
развёртывание Docker Compose. Диаграмма Ганта — часть приложения. Перенос базы 1.0.1 без потерь со сверкой
каждого плана. Подробно: [release notes](docs/release-notes/v0.2.0.md), [для пользователей](docs/versions.md),
[для администраторов](docs/versions_admin.md), [ревизия 1.0.1](docs/review/v0.2.0-revision-1.0.1.md).

### Сервер

- Нормализованная модель данных вместо одного JSON на проект: проекты → планы (бывшие вкладки-версии) →
  строки, пометки, исполнители, комментарии, журнал изменений, снимки ([ADR-0002](docs/architecture/adr-0002-data-model-and-concurrency.md)).
- Правки — пакеты операций, применяются по полям под блокировкой плана: одновременная работа не теряет ничьих
  изменений; конфликты видны; проверка целостности; журнал «кто, когда, было → стало».
- Изменения коллег — опрос раз в 4 секунды, «сейчас на плане»; тихий опрос не пишет в базу.
- Автоматические и ручные снимки плана с восстановлением; архив планов; корзина проектов и планов.
- Серверные сессии в БД с отзывом при отключении сотрудника и смене пароля; CSRF; ограничение попыток входа;
  заголовки безопасности и CSP ([ADR-0003](docs/architecture/adr-0003-sessions-and-security.md)).
- Роли получили смысл: «Наблюдатель» — только просмотр, «Редактор» — работа по выданным доступам; доступы к
  направлениям, без дублей ([ADR-0004](docs/architecture/adr-0004-roles-and-access.md)).
- Перенос базы 1.0.x (`scripts/import_legacy.py`, профиль `migrate`) с обратной выгрузкой и сверкой, репетиция
  `--dry-run` ([ADR-0005](docs/architecture/adr-0005-legacy-migration.md)).
- Производственный календарь РФ 2025–2027 в БД с правкой администратором.

### Клиент

- Vue 3 + Pinia + Vite, дизайн-система todo-planner; окна приложения вместо `confirm`/`prompt`/`alert`.
- Главная с прогрессом проектов; администрирование: сотрудники, направления, доступы, реестр, корзина, LDAP,
  календарь.
- Встроенный редактор Ганта: доменные модули с тестами, SVG со строками по требованию, перетаскивание,
  карточка строки, комментарии, история, фильтры, отмена и повтор, экспорт PNG/PDF/SVG/CSV/JSON
  ([ADR-0006](docs/architecture/adr-0006-native-gantt-editor.md)).

### Надёжность (по итогам независимой проверки)

- Блокировка плана перечитывает план: одновременные пакеты получают разные ревизии, правки коллег не
  пропускаются; повтор уже применённого пакета безопасен.
- Очередь отправки: отклонённая правка не уносит остальные; закрытый план досылает правки в фоне; после
  истечения сессии правки уходят после входа.
- Автосдвиг: циклы связей не сдвигаются, FF/SF-подзадачи не «переворачиваются», сдвиг — только зависящих от
  изменённого; перенос сохраняет длительность.
- Вход: лимит попыток на учётную запись и запасной на адрес, `TRUSTED_PROXY_HOPS`; локальный администратор не
  связывается с каталогом LDAP. Подробно — раздел «Найдено независимой проверкой 0.2» в
  [ревизии](docs/review/v0.2.0-revision-1.0.1.md).

### Развёртывание и качество

- Docker Compose: PostgreSQL 16, backend (gunicorn sync), frontend (nginx), ежедневные резервные копии с
  восстановлением; `deploy/update.sh`.
- CI: ruff + pytest на SQLite и PostgreSQL, Alembic, перенос снимка 1.0.1, eslint + vitest + сборка, e2e
  на Playwright, репетиция установки в Docker.
- Нагрузочное тестирование ([отчёт](docs/performance/loadtest-v0.2.0.md)): переход на процессы sync убрал
  ответы 502 при перезапуске процессов.
- Документация: руководства пользователя, администратора и по развёртыванию (MD, DOCX, PDF), ADR, runbook
  перехода, ревизия 1.0.1.
